# الترجمات والمساهمة بإعدادات محلية { #translations-and-contributing-a-locale }

ترجمات الحزمة، والتعرّف على اتجاه RTL، واللغات التي يتيحها المشروع أمور
منفصلة. تصف هذه الصفحة كلًّا منها، ثم تقدّم أوامر ليشغّلها
المساهمون محليًا. هذه الأوامر تعليمات وليست سجلًا لعمليات
استخراج أو تجميع أو إيداع تغييرات أُجريت من أجل هذا التوثيق.

## الكتالوجات المرفقة واللغات المعروفة { #shipped-catalogs-and-recognized-languages }

تتضمن الحزمة ستة كتالوجات ترجمة ضمن
`src/django_rtl_admin/locale/`. يحتوي كل مجلد على الملف القابل للتحرير
`django.po` والملف المجمّع `django.mo`:

| اللغة | مجلد الكتالوج | ترجمة `Language` |
| --- | --- | --- |
| العربية (`ar`) | `ar/LC_MESSAGES/` | `اللغة` |
| الكردية السورانية (`ckb`) | `ckb/LC_MESSAGES/` | `زمان` |
| العبرية (`he`) | `he/LC_MESSAGES/` | `שפה` |
| الفارسية (`fa`) | `fa/LC_MESSAGES/` | `زبان` |
| الأويغورية (`ug`) | `ug/LC_MESSAGES/` | `تىل` |
| الأردية (`ur`) | `ur/LC_MESSAGES/` | `زبان` |

يترجم كل كتالوج مجموعة رسائل الحزمة كاملةً: تسميات مبدّل اللغة
(`Language` و`Go`)، والاسم الوصفي للتطبيق (`Bilingual / RTL admin`)،
وتسميات الفرز والإجراءات في قائمة السجلات، وتسميات الصفوف المضمّنة. تتبع الرسائل
المشتركة مع لوحة إدارة Django صياغة كتالوج لوحة الإدارة الخاص بـDjango
لتلك اللغة، بحيث تظهر القوالب المستبدلة والافتراضية بصورة متطابقة. تحمل المدخلات
التي كُتبت دون مراجعة متحدث أصلي باللغة ملاحظة `TRANSLATORS` في ملف `.po`
تطلب المراجعة؛ والتصحيحات مرحّب بها. الإنجليزية هي لغة المصدر،
وليست كتالوج `en` منفصلًا مرفقًا بالحزمة، كما لا يوجد كتالوج `ar_EG`
منفصل للحزمة. لا تتضمن الحزمة كتالوج `djangojs`، ولا تحتوي شيفرة JavaScript
الخاصة بمبدّل اللغة على سلاسل نصية مترجمة.

يضمن `tests/test_translations.py` استمرار ذلك: فهو يستخرج الرسائل المعلّمة
من مصدر الحزمة، ويتحقق من أن كل إعداد محلي مرفق يترجمها جميعًا
دون علامات ترجمة غير مؤكدة ومع الحفاظ على العناصر النائبة، ويعيد تجميع كل ملف `.po`
للتحقق من أن ملف `.mo` المودع في المستودع محدّث.

التعرّف على اتجاه RTL أوسع نطاقًا من هذه الترجمات الست. تستخدم دوال الاتجاه المساعدة
`LANGUAGES_BIDI`، والرجوع إلى اللغة الأساسية للرموز الإقليمية، و
`EXTRA_RTL_LANGUAGES`. لا تؤدي إضافة كتالوج في حد ذاتها إلى تسجيل اللغة باعتبارها RTL،
ولا تؤدي إضافة رمز RTL إلى تثبيت ترجمات أو إضافة عنصر إلى القائمة. راجع
[الإعدادات](configuration.md).

يحتوي `LANGUAGES` في المشروع النموذجي على `en` و`ar` و`ar-eg`.
تُرفق كتالوجات الكردية السورانية والعبرية والفارسية والأويغورية والأردية، لكنها غير
مفعّلة في قائمة ذلك العرض التجريبي. دعم أنظمة
الترقيم منفصل أيضًا: يستخدم `ar` وحده عادةً الأرقام اللاتينية، ويستخدم `ar-eg`
الأرقام العربية الهندية، ويستخدم `fa` الأرقام العربية الهندية الموسّعة في دوال
التنسيق المساعدة الصريحة.

## متطلبات المساهمين { #contributor-prerequisites }

استخدم Python 3.10 أو أحدث وإصدارًا من Django متوافقًا مع ذلك المفسّر.
للتثبيت المعتاد للحزمة، راجع [التثبيت](installation.md). لتحرير
الترجمات، اعمل على نسخة محلية من المستودع وثبّتها في بيئة
افتراضية. ابدأ من جذر المستودع باستخدام صدفة متوافقة مع POSIX:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e ".[test]" ruff
```

تثبّت مجموعة الاعتماديات الإضافية `test` مكتبة Babel بالفعل لاختبارات التنسيق. Babel اختيارية
وقت التشغيل، وليست أداة استخراج الترجمات أو تجميعها. تتطلب أوامر
الترجمة في Django **GNU gettext 0.19 أو أحدث**، مع إتاحة `xgettext` و
`msgmerge` و`msguniq` و`msgfmt` ضمن `PATH`. لا يؤدي تثبيت حزمة Python وحدها
إلى تثبيت هذه الملفات التنفيذية الخاصة بالنظام.

على Debian أو Ubuntu:

```sh
sudo apt-get update
sudo apt-get install gettext
```

على macOS باستخدام Homebrew:

```sh
brew install gettext
export PATH="$(brew --prefix gettext)/bin:$PATH"
```

على الأنظمة الأخرى، ثبّت GNU gettext باستخدام مدير الحزم الخاص بالمنصة،
وأتح ملفاته التنفيذية للصدفة. بعد تفعيل بيئة المساهم،
تحقق من الأدوات قبل استخراج الرسائل:

```sh
django-admin --version
xgettext --version
msgmerge --version
msguniq --version
msgfmt --version
```

## تحديث إعداد محلي قائم للحزمة { #refresh-an-existing-package-locale }

شغّل أوامر ترجمة الحزمة من **`src/django_rtl_admin`**، وليس من
`example/`. ابدأ من جذر المستودع:

```sh
cd src/django_rtl_admin
django-admin makemessages -l ar
```

يفحص هذا ملفات Python وقوالب الحزمة ويحدّث
`locale/ar/LC_MESSAGES/django.po`. يحول الالتزام بمجلد العمل هذا دون خلط
رسائل النماذج والحقول الخاصة بمكتبة المشروع النموذجي مع كتالوج الحزمة.

حرّر ملف `.po` الناتج:

1. ترجم الرسائل الجديدة أو المعدّلة وراجع المدخلات القائمة.
2. احتفظ بمعرّفات الرسائل، والعناصر النائبة لاستيفاء القيم، وأي ترميز
   يجب أن يبقى سليمًا.
3. راجع البيانات الوصفية الخاصة باللغة والترميز والمترجم وصيغ الجمع بحسب
   الحاجة. استخدم UTF-8 وهوية الإعداد المحلي الصحيحة في gettext.
4. راجع المدخلات غير المؤكدة ولا تزل علامة عدم التأكد إلا بعد التحقق من
   الترجمة. لا تُجمّع الرسائل غير المؤكدة افتراضيًا.

وأنت لا تزال في `src/django_rtl_admin`، جمّع الكتالوج بعد مراجعته:

```sh
django-admin compilemessages -l ar
```

الملف الناتج هو `locale/ar/LC_MESSAGES/django.mo`. استبدل الرمز بـ`ckb` أو `he` أو `fa`
أو `ug` أو `ur` لاستخدام إعداد محلي قائم آخر. راجع الفروق وأدرج **ملفَي
`.po` و`.mo` معًا** في مساهمتك؛ ولا تحرّر ملف `.mo` الثنائي مباشرةً.

## إضافة إعداد محلي جديد للحزمة { #add-a-new-package-locale }

من مجلد العمل نفسه `src/django_rtl_admin`، على سبيل المثال:

```sh
django-admin makemessages -l ps
```

ترجم الملف الناتج `locale/ps/LC_MESSAGES/django.po` وراجع بياناته الوصفية
ومدخلاته غير المؤكدة كما سبق. ثم جمّعه:

```sh
django-admin compilemessages -l ps
```

أدرج كتالوجَي المصدر والنسخة المجمّعة الجديدين في مساهمتك. يستخدم الإعداد المحلي
الإقليمي في gettext اسمًا مثل `ar_EG`، بينما يستخدم إعداد اللغة في Django
`ar-eg`. لا تنشئ كتالوجًا إقليميًا إلا عند الحاجة إلى ترجمة متميزة؛
فاختيار `ar-eg` لا يتطلب تكرار كتالوج العربية القائم.

لتحديث جميع الكتالوجات القائمة، أو تجميع جميع الكتالوجات بعد مراجعتها، شغّل
الأوامر التالية من `src/django_rtl_admin`:

```sh
django-admin makemessages -a
django-admin compilemessages
```

استخدم أمرًا خاصًا بإعداد محلي واحد لمساهمة ترجمة محددة النطاق. راجع أي
تغييرات في الكتالوجات الأخرى قبل تضمينها. لا يوجد أمر لإدارة الترجمات خاص
بالحزمة؛ فهذه أوامر Django القياسية.

## إتاحة اللغة في مشروع Django { #offer-the-language-in-a-django-project }

اضبط اللغات المتاحة بصورة مستقلة عن ملفات الكتالوجات. ادمج قائمة
مناسبة في إعدادات مشروعك، على سبيل المثال:

```python
USE_I18N = True
LANGUAGE_CODE = "en"
LANGUAGES = [
    ("en", "English"),
    ("ar", "Arabic"),
    ("ar-eg", "Arabic (Egypt)"),
    ("ckb", "Kurdish (Sorani)"),
    ("he", "Hebrew"),
    ("fa", "Persian"),
    ("ug", "Uyghur"),
    ("ur", "Urdu"),
]
```

اتبع [البدء السريع](quick-start.md) لترتيب التطبيقات، ووضع `LocaleMiddleware` بعد
الجلسات وقبل البرمجية الوسيطة المشتركة، وإضافة نقطة النهاية القياسية `set_language`.
أبقِ `USE_I18N=True`. عند تثبيت تطبيق الحزمة، يستطيع Django اكتشاف
كتالوجاتها المجمّعة؛ أما تسميات النماذج ونصوص المساعدة الخاصة بالمشروع فمكانها
كتالوجات تطبيقك نفسه، وليس بالضرورة كتالوج هذه الحزمة.

يتيح مبدّل اللغة افتراضيًا لغات `LANGUAGES`. يمكنك تقييد القائمة أو عرض
التسميات الأصلية والمضبوطة معًا من خلال إعدادات `RTL_ADMIN` القائمة:

```python
RTL_ADMIN = {
    "LANGUAGE_SWITCHER_LANGUAGES": ["en", "ar-eg", "fa"],
    "LANGUAGE_SWITCHER_LABELS": "both",
}
```

ادمج هذه المفاتيح مع أي إعدادات أخرى للحزمة. لا يؤدي تخصيص القائمة إلى تفعيل
لغات خارج دعم اللغات المضبوط في Django أو تثبيت ترجمات.
احتفظ باللغات المتاحة ضمن `LANGUAGES`. تأتي التسميات الأصلية عادةً من البيانات
الوصفية للغات في Django، وليس من كتالوج الحزمة. راجع
[الإعدادات](configuration.md#language-switcher) لمعرفة أنماط التسميات، و
[وسوم القوالب ومرشحاتها](template-tags.md) لدمج مبدّل لغة مخصص.

إذا كان الرمز لا يتعرّف عليه Django باعتباره RTL، فراجع
[الإعدادات](configuration.md#styling-and-direction) قبل إضافة
`EXTRA_RTL_LANGUAGES`. لا تستخدم هذا الإعداد إلا إذا كان نظام الكتابة المقصود
من اليمين إلى اليسار فعلًا؛ فإنشاء الكتالوج واختيار نظام الترقيم لا يدلان على اتجاه
النص.

## الفحوصات اليدوية للإعدادات المحلية { #manual-locale-checks }

جمّع الكتالوج قبل الاختبار وأعد تشغيل خادم التطوير الجاري إذا
كان قد حمّل الترجمات بالفعل. بالنسبة إلى العرض التجريبي في المستودع، أضف الإعداد المحلي إلى
`example/config/settings.py` لإجراء فحصك المحلي؛ إذ لا تتضمن قائمته الافتراضية
الفارسية أو الأردية. ابدأ من جذر المستودع بعد تفعيل بيئة
المساهم:

```sh
cd example
python manage.py migrate
python manage.py demodata
python manage.py check
python manage.py runserver
```

استخدم حساب العرض التجريبي المحلي `demo` / `demo12345` على `/admin/`؛ فبيانات
الاعتماد هذه مخصصة للعرض التجريبي فقط. لا تتضمن الحزمة أمرًا منفصلًا لعرض الترجمات تجريبيًا.

تحقق مما يلي باللغة قيد المراجعة ثم مجددًا بالإنجليزية:

- يُدرج مبدّل اللغة في صفحة تسجيل الدخول والمبدّل بعد المصادقة اللغة المقصودة، ويضعان علامة
  اختيار عليها، ويعرضان الاسم الأصلي أو المضبوط المتوقع.
- يحافظ تبديل اللغة على مسار لوحة الإدارة وسلسلة معاملات الاستعلام حيث ينطبق ذلك،
  ويستمر الاختيار في طلب لاحق من خلال ملف تعريف الارتباط الخاص باللغة
  والبرمجيات الوسيطة في Django.
- عند تعطيل JavaScript، يظل زر إرسال مبدّل اللغة قابلًا للاستخدام. وعند
  تفعيل JavaScript، يؤدي تغيير الاختيار إلى إرسال النموذج.
- تُترجم تسمية `Language` في مبدّل اللغة. تحقق أيضًا من `Go` وتسميات
  الفرز والإجراءات في قائمة السجلات وتسميات الصفوف المضمّنة؛ إذ يجب أن تظهر الرسائل المشتركة
  مع لوحة الإدارة الافتراضية بصورة متطابقة، سواء أتت من كتالوج هذه
  الحزمة أم من كتالوج Django نفسه.
- يكون اتجاه الواجهة، والمسافات حول الأيقونات، وعلامات الترقيم في التسميات، ونصوص المساعدة، والمحتوى
  الطويل مقروءًا عند عروض شاشات الحاسوب والعروض الضيقة. افحص نموذج تعديل
  فعليًا إلى جانب قائمة السجلات.
- تظل المعرّفات المعزولة صراحةً مقروءة؛ أما النصوص العادية والقيم المؤلفة من أرقام فقط
  والنصوص التي تجمع أنظمة كتابة مختلفة فتحتاج إلى فحوصات منفصلة. راجع
  [BidiSafeAdminMixin](admin-mixin.md) لمعالجة العرض المفعّلة صراحةً.
- تستخدم دوال التنسيق المساعدة الصريحة أشكال الأرقام وأنماط العملات والتواريخ
  المقصودة. لا تتوقع أن يحوّل اختيار الإعداد المحلي كل رقم في لوحة الإدارة.
  قد تختلف المخرجات بوجود Babel عنها بدونه؛ راجع [واجهة Python البرمجية](api.md).

سجّل إصدار Django والمتصفح ورمز الإعداد المحلي وتوفر Babel والصفحة
المتأثرة عند الإبلاغ عن مشكلة في التخطيط. لقطات الشاشة الإنجليزية والعربية القائمة
تقدّم نظرة عامة، وليست مقارنات مع حالة لوحة الإدارة الافتراضية قبل تطبيق الحزمة، ولا تغطي كل إعداد محلي. راجع
[عيوب RTL في لوحة الإدارة الافتراضية](rtl-defects.md) لمعرفة نطاق المقارنة على مستوى المصدر
والقيود المعروفة.

## فحوصات المساهمة { #contribution-checks }

من جذر المستودع، بعد تفعيل بيئة المساهم:

```sh
pytest
ruff check .
```

يوثّق `CONTRIBUTING.md` في المستودع أيضًا اختبارًا اختياريًا للمسار البديل في
بيئة مساهم مؤقتة يمكن الاستغناء عنها. يزيل هذا الاختبار Babel مؤقتًا ثم
يعيد تثبيته:

```sh
python -m pip uninstall -y Babel
pytest
python -m pip install "Babel>=2.12"
```

لمساهمة محددة النطاق في إعداد محلي، راجع ملفَي الكتالوج وأدرجهما في
طلب السحب نفسه، وصِف الفحوصات اليدوية التي أجريتها. أضف التغييرات التي يلاحظها المستخدم
تحت `## [Unreleased]` في `CHANGELOG.md`، وأبقِ التغييرات الناتجة آليًا وغير ذات الصلة
خارج المساهمة، واتبع قائمة التحقق لطلبات السحب في المستودع. أودع
ملفَي `.po` و`.mo` معًا؛ فالتجميع لا يغني عن مراجعة النص
المترجم.

## بناء التوثيق { #building-the-documentation }

من جذر المستودع، ثبّت مجموعة اعتماديات التوثيق الإضافية وشغّل البناء
الصارم نفسه المستخدم في التكامل المستمر:

```sh
python -m pip install -e ".[docs]"
mkdocs build --strict
```

يُكتب الموقع الناتج في `site/`، الذي يتجاهله Git. لمعاينة
التغييرات محليًا مع إعادة تحميل تلقائية:

```sh
mkdocs serve
```

يوفّر MkDocs Material التنقل والبحث. يبدّل محدّد اللغة
بين الإنجليزية والعربية؛ تتوفر جميع صفحات التوثيق بالعربية باستثناء صفحة واجهة Python
البرمجية وسجل التغييرات، اللذين يبقيان باللغة الإنجليزية. تحقق من أن الصفحات العربية تظهر مع
`lang="ar"` و`dir="rtl"` وأن أمثلة الشيفرة تظل مقروءة.

يُولّد توثيق واجهة Python البرمجية من `src/` باستخدام mkdocstrings. تتضمن
صفحة سجل التغييرات ملف المستودع المرجعي `CHANGELOG.md` وقت البناء؛
حدّث ذلك الملف بدلًا من تكرار ملاحظات الإصدارات في `docs/changelog.md`.
يستخدم Read the Docs ملف `.readthedocs.yaml` لتثبيت مجموعة اعتماديات الحزمة الإضافية `docs` على
Ubuntu 24.04 مع Python 3.12 وبناء `mkdocs.yml`، ويفشل البناء عند وجود تحذيرات.

## ترجمة التوثيق إلى العربية { #translating-the-documentation-into-arabic }

ترجمة التوثيق منفصلة عن كتالوجات gettext الخاصة بـDjango. يستخدم موقع
التوثيق توطينًا قائمًا على لاحقة اسم الملف: فالنسخة العربية من `quick-start.md` هي
`quick-start.ar.md`. تتبع جميع صفحات التوثيق العربية هذا العرف؛ وتبقى صفحة واجهة
Python البرمجية وسجل التغييرات باللغة الإنجليزية.

لترجمة صفحة أخرى:

1. احتفظ بالصفحة الإنجليزية المرجعية وأنشئ ملفًا شقيقًا لها باللاحقة `.ar.md`،
   مثل `translations.ar.md` إلى جانب `translations.md`.
2. ترجم النصوص والعناوين والتعليقات التوضيحية والنصوص البديلة المفيدة. حافظ على دقة أسماء Python،
   ومفاتيح الإعدادات، ورموز الإعدادات المحلية، والأوامر القابلة للتنفيذ بدلًا من
   ترجمة المعرّفات.
3. اربط بأسماء الصفحات المرجعية مثل `[الإعدادات](configuration.md)` و
   `[البدء السريع](quick-start.md)`، وليس بعناوين المخرجات ذات بادئة اللغة أو
   روابط تستهدف `.ar.md`. تحلّ إضافة توطين التوثيق الروابط إلى النسخ اللغوية المناسبة.
4. أعد استخدام أسماء ملفات لقطات الشاشة حيث يلائم ذلك، واحتفظ بتعليقات توضيحية صادقة بشأن
   لغتها ونطاق تغطيتها. ترجم التعليقات التوضيحية دون تغيير ما
   تثبته الصورة.
5. راجع العرض العربي والروابط ومعرّفات ارتساء العناوين في معاينة التوثيق
   قبل التقديم. تحقق من الروابط إلى أجزاء الصفحات عندما تتغير العناوين المترجمة.

لا يمر توثيق Markdown عبر `makemessages` أو `compilemessages`.
ولا يؤدي تعديل صفحة توثيق إلى إضافة إعداد محلي وقت التشغيل في Django، كما لا تؤدي إضافة كتالوج `.po`
إلى ترجمة موقع التوثيق.
